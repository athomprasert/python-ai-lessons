How A2A Policies Govern a Single Agent-to-Agent Exchange

Step-by-step: what happens to one task request as it travels Client Agent → Omni Gateway → Target Agent, and back

🤖Client AgentInitiates the task
MuleSoft Omni Gateway — A2A Policy Chain
Every A2A request and response is intercepted here before reaching either agent
🎯Target AgentExecutes the task
① Discovery — before any task is sent
0
0Agent Card Rewrite
Client fetches the target agent's Agent Card. The gateway rewrites every interface URL in it to its own public address — so the client always calls back through the gateway, never the agent's internal endpoint.
A2A Agent Card · A2A v1 Agent Card
② Request ingress — task sent by the Client Agent
1
1Protocol Bridge & Schema Validation
If the client speaks A2A v1 and the backend speaks v0.3 (or vice versa), the transcoder translates the JSON-RPC message bidirectionally. The request is then checked against the A2A specification — malformed messages are rejected here.
A2A v1 to v0.3 Transcoder · A2A / A2A v1 Schema Validation
→
2Token Rate Limit Check
Before any processing continues, the gateway checks whether this caller has budget remaining under its token-based usage cap for upstream resources.
A2A Token Based Rate Limit · A2A v1 Token Based Rate Limit
→
3PII Detection
The request content is scanned for personally identifiable information. If PII is found, the request is blocked before it ever reaches the target agent.
A2A PII Detector · A2A v1 PII Detector (all transports)
4
4Content Guardrails
The message is evaluated against Azure AI Content Safety or Amazon Bedrock Guardrails — checking for harmful content, jailbreak attempts, hallucination risk, and copyrighted material.
A2A v1 Azure Content Guardrails · A2A v1 Bedrock Guardrails
→
5Prompt Decoration
Approved requests are enriched with additional context — organization-wide instructions, compliance language, or routing metadata — injected transparently before the prompt reaches the agent.
A2A Prompt Decorator · A2A v1 Prompt Decorator
→
⚙️ Target Agent Executes Runs the task — may call tools, MCP servers, or an LLM
③ Response egress — result returned by the Target Agent
6
6Guardrails Re-Check
Bedrock Guardrails evaluates the completed response the same way it evaluated the request — content safety and contextual grounding checked on the way out, not just the way in.
A2A v1 Bedrock Guardrails (response path)
→
7Quality Evaluation
Once the task response is complete, an LLM scores it for quality and completeness — an audit signal for monitoring whether agents in the fleet are actually doing their job well, not just responding.
A2A v1 Quality Evaluation
→
↩️ Response Delivered Back to the Client Agent
Continuous, throughout the exchange: Agent Connection Telemetry & SSE Logging — every event in the request, response, and any streamed updates is logged for observability and audit
