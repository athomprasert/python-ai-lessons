The solution in one sentence
The customer keeps building on Claude exactly as they do today. MuleSoft becomes the governed connective tissue on both sides of the agent — the tools it calls out to (MCP), and the door others call in through (A2A) — with credentials held and refreshed by the platform, never carried by hand.

The credential story — why it's seamless, not bolted-on

The part that makes this "seamless" is that nobody hand-carries a key. There are three trust boundaries, and a platform owns each one — issuing and refreshing the credential automatically.

HopWho authenticates whomHeld & refreshed by
Consumer → MuleSoftThe caller proves who it isOmni Gateway — the customer's existing policy plane (per-consumer auth, rate-limit, audit)
MuleSoft → AnthropicThe wrapper proves it's your Anthropic accountWIF — the Mule workload exchanges an IdP JWT for a short-lived sk-ant-oat01 token. No static sk-ant-api… to rotate.
Claude → MuleSoft's backend toolsThe agent presents the backend credentialAnthropic Vaults — injected at egress, never enters the sandbox; OAuth auto-refresh

Every credential is issued and rotated by a platform — the Gateway, Anthropic's WIF exchange, or the Vault. That is the seamless part: no shared secret sits in an env file waiting to be manually rotated.

How WIF works, in four steps
  1. The Mule workload holds an OIDC JWT from an identity provider (IdP).
  2. It POSTs that JWT to Anthropic's /v1/oauth/token (grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer) with your federation_rule_id, organization_id, and service_account_id.
  3. Anthropic returns a short-lived sk-ant-oat01-… bearer token (default 1h), sent as Authorization: Bearer.
  4. Re-exchange near expiry. No sk-ant-api… key to mint or hand-rotate. One-time Console setup: a service account, a federation issuer (points at your IdP's JWKS), and a federation rule (a match block on the JWT's sub/aud/claims).

The one honest caveat to carry into the room

WIF's hard requirement: the Mule workload must present an IdP-issued OIDC JWT whose issuer exposes a public JWKS Anthropic can reach (or you register keys inline). Whether that's clean depends on where you deploy — and Mule has no Anthropic SDK, so in a pure HTTP-Request flow you own the token exchange + caching (do it once, cache the sk-ant-oat01 token in an Object Store with TTL from expires_in; or run the exchange in a small anthropic-java module, which does WIF natively).

The SE talk track

"Claude is the brain. MuleSoft is the governed nervous system around it — the tools it reaches, the door others reach it through, and the identity layer so no one emails an API key. On one side, your existing Anypoint APIs become agent-callable tools with no new code, and every call runs through Omni Gateway. On the other, a thin front door makes your Claude agent discoverable in the Registry and gated at ingress. Credentials are held by the platform end to end — the Gateway authenticates your consumers, Workload Identity Federation mints short-lived tokens to Anthropic so there's no static key to rotate, and Vaults keep backend secrets out of the model's sandbox entirely. You don't rebuild your agent; you drop it into a fabric you already know how to run."
The strategic frame
Don't sell this as a new product category — sell it as API-led connectivity for agents. Omni Gateway is API Manager for agents; the Agent Registry is Exchange for agents; the Agent Broker is orchestration for agents. The customer who bought "govern your API sprawl" already understands "govern your agent sprawl." Familiar shapes, new traffic — and the credential story means it's governed without anyone hand-carrying secrets.
